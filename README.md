# 拣分站 · 文件批量整理器

拖进来一批文件，按类分开，**只复制、不动原件**。Windows 桌面应用（Electron + TypeScript，纯前端 + 本地逻辑，无服务端）。

```
拖入文件 / 文件夹 → 选输出目录 → 一键「AI 分拣」或「规则分拣」
        → 预览里手动调结构 → 确认分拣 →（可选）删源文件 → 可撤销
```

---

## 三条硬规矩

这项目的所有设计都围着这三条转，改代码时也别破：

1. **只复制，不动原件。** 全程序默认一个删除都不做；「删源文件」是唯一会动原件的动作，必须先勾选确认、再弹一次确认，且只删「这一次复制成功」的那几个文件、删前逐个核对输出里那份还在、默认进回收站（拿不到回收站能力就一个都不删）。
2. **危险方向直接拦住。** 输出目录若是某个源文件夹本身、或在源文件夹内部，界面出红条、**根本不出方案**、一个字节都不写。
3. **发给 AI 的只有元数据。** 只发文件名、大小、修改时间，外加原文件夹里已有的分类目录名（好让 AI 沿用你已经分好的类）；**不读不发文件内容，不发绝对路径、不发盘符**。

## 快速开始

环境：Windows + Node 22 以上（仓库自带 Electron 44 与 TypeScript，无需另装）。

```bash
npm install     # 装依赖
npm run build   # 编译到 out/
npm start       # 启动（= 先 build 再拉起 Electron）
npm run dev     # 开发模式：改完自动重编译 + 窗口自动刷新
npm run icon    # 改完 assets/icon.svg 后，重新生成 icon.png / icon.ico
npm run 验收    # 跑全部 21 条验收（PowerShell）
```

没有打包配置（未接 electron-builder），要从 `out/` 跑。

## 界面：一页到底

侧栏四个入口（投递 / 规则 / 历史单号 / 设置），主页面从上到下就是流程本身：

| 区块 | 干什么 |
| --- | --- |
| 投递站 | 拖入文件与文件夹、选输出目录、看名单 |
| 分拣台 | `AI 分拣` / `规则分拣` 两个按钮；出方案**不落盘** |
| 预览 | 关系链球：拖球连线即可改层级（文件拖进分类、分类拖成子分类），右侧面板可 移到 / 改名 / 新建子分类 / 删除分类 / 挂到 / 挪回顶层；改完结构**不会自动重排**，点「重排」才恢复整齐布局 |
| 本次结果 | 落盘清单、删源文件（红框，二次确认）、撤销本次整理、历史单号 |

## 两种分法

**规则分拣**：默认规则表按后缀分组，五类固定（`01_图片` / `02_文档` / `03_音视频` / `04_压缩包` / `05_其他`），顺序即优先级，第一条命中的生效。规则可增删改顺序、可停用；条件支持后缀 / 文件名 / 大小 / 修改时间四种组合。分类名**支持多级相对路径**（写 `照片\风光` 就逐层建目录）。

**AI 分拣**：在「设置」里填接口地址、模型、密钥（存在本机 userData 下，见下）。它会优先沿用原文件夹里已经分好的分类，名字一字不改地沿用；确实不属于任何已有分类时才另起新名。AI **只出方案不落盘**，你在预览里改完、点「确认分拣」才写盘。

## 目录结构

```
src/core/       纯逻辑：分类、规则、复制、预览、撤销、删源、历史
                —— 不依赖 Electron，node 里能直接 require，验收就是这么跑的
src/main.ts     Electron 主进程：只做「界面 + 把纯逻辑串起来」
src/preload.ts  给界面用的窄接口（contextIsolation 开着）
src/renderer/   界面：index.html / renderer.ts（含关系链球）/ planGraph.ts（方案的纯数据）/ style.css
scripts/        21 条验收脚本 + 构建脚本（copy-assets / build-icon / dev）
assets/         图标：icon.svg 是唯一手写源，icon.png / icon.ico 由 npm run icon 生成
ENGINEERING-LOG.md  逐片的工程记录（为什么这么改、踩过什么坑）
```

## 数据都放哪

程序运行时的数据一律写在 Electron 的 userData 目录（`C:\Users\<你>\AppData\Roaming\file-organizer\`），**不在项目目录里，也不进 git**：

| 文件 | 内容 |
| --- | --- |
| `organizer-ai.json` | AI 的接口地址 / 模型 / **密钥**（本机明文保存，只在本机） |
| `organizer-rules.json` | 你编辑过的分类规则 |
| `organizer-last-run.json` | 上一次整理的记录（撤销靠它） |
| `organizer-history.json` | 历史单号 |
| `organizer-delete-audit.log` | 删除审计：撤销或删源文件删掉的每一个文件都记一行 |

`.gitignore` 里这些名字被显式钉在忽略名单末尾，防止以后放宽白名单时被带进仓库。

## 验收

`npm run 验收` 跑 21 条断言（纯逻辑 / 真造临时目录 / 真界面桩 / 本机假接口），每条都有**坏样本探针**反证——不是「能跑通就算过」，而是「写错了必须能被判失败」。已覆盖：分类逻辑、真实复制、拖入取路径、规则引擎与编辑器、文件夹各归各、预览不落盘、输出方向、撤销、嵌套规则、AI 策略/界面/真调用/配置/落地/结构、热加载、删源文件、软件图标。

## 已知边界

- 只测过 Windows；打包（exe / 安装包）还没做。
- 符号链接：core 里用的是 `stat` 而不是 `lstat`，某些环境下第 8 条验收会报「符号链接被跟随」。
- 沙箱化的终端里 Electron 起得来与否取决于环境（本机需要 `ELECTRON_DISABLE_SANDBOX`）；`out/.dev-userdata` 被残留进程占用会让 `npm run clean` 失败，先杀掉本项目残留的 electron 进程。
